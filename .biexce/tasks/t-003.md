# t-003 — Implement text posts, current audience authorization, and feed

## 1. Objective

Deliver text-post creation/read/update/delete and a bounded deterministic feed that exposes each post only to its author or currently valid friends according to `ONLY_ME` and `FRIENDS`, rechecking block and friendship policy on every read path.

## 2. Context tối thiểu

- Use authentication/error/database infrastructure from `t-001` and the reusable current friendship/block policy from `t-002`.
- Scope authority: `TING_TING_MVP_SCOPE.md` section 4.3 and applicable sections 5–6; master-plan criteria `TT-POST`, `TT-FEED`, `TT-BLOCK`, `TT-API-QUALITY`, and `TT-TEST`.
- Post content is text only. Accepted audiences are exactly `ONLY_ME` and `FRIENDS`. Only the author may edit or delete a post.
- `ONLY_ME` is author-only. `FRIENDS` is visible to the author and users who are still friends and not blocked at read time. Possessing a post ID or having seen a prior feed page confers no access.
- Feed is newest first with a stable secondary ID tie-breaker. Use validated bounded `limit`/`offset` pagination or an equally simple documented mechanism, and apply visibility before selecting each page.
- Expected areas are post models/schemas/services/routes, feed query/policy integration, and tests. Return sufficient author, audience, timestamps, text, and initial interaction summary fields for the later web and interaction tasks without exposing private identity data.

## 3. Acceptance criteria

- [ ] **AC1 (`TT-POST`, automated integration):** Given an authenticated author and valid non-empty bounded text with either allowed audience, when creating a post, then one text-only post is persisted and returned with author, audience, timestamps, and create status; empty/oversized text or any other audience is rejected without a row.
- [ ] **AC2 (`TT-POST`, automated integration):** Given a post, when its author edits its allowed fields or deletes it, then the persisted/public result changes accordingly; when another user attempts either action, it is denied and the post remains unchanged; an unknown post follows the consistent missing-resource contract.
- [ ] **AC3 (`TT-POST`, automated policy/integration):** Given `ONLY_ME`, when author, friend, non-friend, blocked peer, or anonymous actor requests it or receives a feed, then only the author can read it.
- [ ] **AC4 (`TT-POST`, automated policy/integration):** Given `FRIENDS`, when author, current friend, non-friend, blocked peer, or anonymous actor reads it, then only author and current unblocked friend can do so.
- [ ] **AC5 (`TT-BLOCK`/`TT-FEED`, automated integration):** Given a friend has previously read a `FRIENDS` post, when the pair unfriends or either blocks the other, then direct reads and subsequent feed requests immediately omit/deny it; unblocking alone does not restore visibility.
- [ ] **AC6 (`TT-FEED`, automated integration):** Given interleaved visible and invisible posts including equal timestamps, when requesting successive bounded pages, then results contain only authorized posts, order is deterministically newest-first with the documented tie-breaker, limits are enforced, and visibility filtering precedes pagination.
- [ ] **AC7 (`TT-API-QUALITY`, automated integration):** Anonymous mutations/feeds are unauthenticated, forbidden and hidden/missing resources follow the documented non-leaking error behavior, and replayed delete cannot corrupt unrelated data.
- [ ] **AC8 (`TT-TEST`, automated test):** Focused unit tests cover audience policy and integration tests cover AC1–AC7, including social-state transitions after post creation.

Verify: **planned and unexecuted at plan time; use the canonical command established by `t-001`:** `.venv/bin/python -m pytest tests/unit tests/integration -k 'post or audience or feed'`.

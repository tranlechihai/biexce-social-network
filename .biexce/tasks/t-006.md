# t-006 — Audit mandatory coverage and produce pre-Gate-2 verification evidence

## 1. Objective

Independently verify every mandatory criterion across API, persistence, and browser boundaries; add only missing or insufficient test/checklist coverage; and produce reproducible regression, fresh-seed, and browser-smoke evidence for integration review without changing product behavior to make tests pass.

## 2. Context tối thiểu

- `t-001` through `t-005` deliver source, feature tests, canonical commands, README, seed data, and a draft smoke checklist. This task is the quality owner and does not implement or repair product source.
- Scope authority: all mandatory sections 4–6 and Definition of Done in `TING_TING_MVP_SCOPE.md`; traceability IDs and verification approach are in `.biexce/MASTER_PLAN.md` sections 5–6. Section 7 remains excluded.
- Audit existing tests before adding cases. Preserve all prior tests; do not delete, skip, loosen assertions, or change expected outcomes to match defects. A discovered product defect is reported with a minimal reproduction for bx-fix rather than repaired under this task.
- Required automated evidence includes unit rules for social graph/audience/ownership; integration flows for auth, friend request, block, post/feed, like/comment; and negative anonymous, forbidden, validation/conflict/replay, and missing-resource behavior.
- High-risk combined scenarios include: friendship accepted then removed; content created before block; unblock without restored friendship; visibility-safe pagination with interleaved hidden posts; repeated request/like/unlike/seed operations; post-owner versus comment-owner deletion; consistent counters; both bearer and cookie auth.
- Execute the README from a fresh environment/database where feasible, run the complete regression suite, execute/finalize the browser smoke checklist at desktop and narrow-mobile viewports, and record command/result summaries in the established test evidence/checklist area. No production, compliance, load, or external baseline evidence is required.

## 3. Acceptance criteria

- [ ] **AC1 (`TT-AUTH`/`TT-PROFILE`, automated evidence):** The audit maps and passes tests for registration uniqueness/hash safety, username/email login, bearer/cookie auth and logout, anonymous/invalid token behavior, owned profile update, validation, and non-sensitive errors/logs.
- [ ] **AC2 (`TT-SOCIAL`/`TT-BLOCK`, automated evidence):** The audit maps and passes tests for every request state/role, self/duplicate/replay constraints, bidirectional friendship/unfriend, block cleanup/bilateral denial, and unblock-without-restoration.
- [ ] **AC3 (`TT-POST`/`TT-FEED`, automated evidence):** The audit maps and passes tests for text validation, author-only mutation, both audiences across actor roles, current friendship/block transitions, direct-read non-leakage, stable newest-first ordering, and visibility-before-pagination.
- [ ] **AC4 (`TT-LIKE`/`TT-COMMENT`, automated evidence):** The audit maps and passes tests for authorized and forbidden interactions, replay-safe like/unlike, comment create/list, deletion role matrix, missing resources, social-state transitions, and persisted count/state consistency.
- [ ] **AC5 (`TT-WEB`, automated + manual evidence):** Automated web tests and the completed checklist demonstrate all mandatory browser flows, clear validation/error display, cookie logout, and usable desktop/narrow-mobile layouts without manual API calls; viewport sizes and observed results are recorded.
- [ ] **AC6 (`TT-SEED-DOC`, command evidence):** Following README from a fresh database successfully installs/configures, seeds at least three representative users and required relationships/content/interactions, verifies a second seed invocation is safely refused without mutation, starts the app for smoke testing, and identifies usable demo-account instructions.
- [ ] **AC7 (`TT-API-QUALITY`, audit evidence):** Status/error shape and server authorization are consistent; important retries do not duplicate data; secret/credential logging or committed hard-coded secrets are absent; modules remain responsibility-oriented; every explicit section 7 item is confirmed not implemented.
- [ ] **AC8 (`TT-TEST`, command/result evidence):** Full unit and integration regression runs with no test removed, skipped, or weakened to obtain PASS; the criterion matrix records evidence for all `TT-*` rows and unresolved failures are reported as blockers/reproductions rather than represented as success.

Verify: **planned and unexecuted at plan time; use README's implemented canonical commands:** `.venv/bin/python -m pytest tests/unit && .venv/bin/python -m pytest tests/integration && .venv/bin/python -m pytest`. Also execute the documented fresh-seed command and browser smoke checklist. Record actual outputs/results for integration review; this story does not pre-claim PASS.
